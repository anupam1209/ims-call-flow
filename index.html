01 UE Registration REGISTER · 401 · SAR/SAA · 3rd-party reg
Registration ka matlab kya hai?
Registration mein UE apne aap ko IMS core se introduce karta hai — bilkul naye employee ka ID card banana. Yeh flow do rounds mein hota hai: pehle 401 Challenge aata hai (authentication ke liye), phir credentials ke saath dobara REGISTER bhejte hain.

Step 1 UE → P-CSCF → I-CSCF: REGISTER. I-CSCF ka kaam hai HSS se UAR/UAA (Cx Diameter) karke pata lagana ki is subscriber ko kaunsa S-CSCF serve karega.
Step 2 I-CSCF → S-CSCF: REGISTER. S-CSCF HSS se MAR/MAA karta hai — authentication vectors milte hain (AKA challenge). 401 bhejta hai UE ko challenge ke saath.
Step 3 UE dobara REGISTER bhejta hai — is baar credentials ke saath. S-CSCF HSS se SAR/SAA karta hai — user ka iFC profile milta hai (Initial Filter Criteria).
Step 4 S-CSCF iFC check karta hai → TAS ka entry milta hai → 3rd-party REGISTER TAS ko bhejta hai. TAS ko pata chalta hai ki yeh subscriber registered hai. Phir 200 OK wapas UE tak pahunchta hai. P-CSCF Service-Route header store karta hai — aage ke INVITE seedha S-CSCF ko jayenge.
02 MO Call Setup — UE1 dials UE2 (+919952000068) INVITE · iFC · TAS→SCSCF · LIR · t≈27.12s
INVITE ka safar — orig iFC se term iFC tak
Yeh phase sabse important hai. INVITE ek hi message hai lekin bohot saare hops se guzarta hai.

Originating Side P-CSCF seedha S-CSCF ko INVITE bhejta hai — I-CSCF ko bypass karta hai (Service-Route use hoti hai registration se). S-CSCF UE1 ke originating iFC check karta hai → TAS match hota hai → INVITE TAS ko bhejta hai. TAS originating services apply karta hai (call barring, ODB check, CLIR, prepaid validation). TAS kaam khatam karke INVITE wapas S-CSCF ko bhejta hai — yahi key correction hai (TAS → S-CSCF, not I-CSCF).

Terminating Routing Ab S-CSCF ko UE2 ka address dhundna hai. Isliye I-CSCF ko INVITE bhejta hai. I-CSCF HSS se LIR/LIA (Location-Info-Request/Answer) Diameter query karta hai — "UE2 (+919952000068) ka S-CSCF kaun sa hai?" HSS answer deta hai, I-CSCF S-CSCF ko INVITE route karta hai.

Terminating iFC UE2 ka S-CSCF terminating iFC check karta hai → TAS match → INVITE TAS ko bhejta hai. TAS terminating services check karta hai (call divert, call waiting, call barring incoming, PRBT flag). TAS → S-CSCF → P-CSCF → UE2: INVITE deliver hota hai.
03 Session Progress — 183 · PRACK · UPDATE · 180 Ringing RFC 3262 PRACK · SDP offer/answer · t≈27.4–27.8s
Ringing phase mein kya kya negotiate hota hai?

183 Session Progress UE2 se aata hai SDP answer ke saath — matlab UE2 bolta hai "mujhe INVITE mila, yeh mera media port/codec hai." Yeh message Record-Route ke through wapas jaata hai: UE2 → P-CSCF → S-CSCF → TAS → S-CSCF → P-CSCF → UE1. Saath hi TAS Announcement Server (10.220.10.30) ko INVITE karta hai — UE1 ko ringback tone sunane ke liye.

PRACK 183 ek reliable provisional response hai (RFC 3262). Isliye UE1 PRACK bhejta hai confirm karne ke liye ki 183 mila. PRACK bhi same Record-Route path se guzarta hai. UE2 200 OK bhejta hai PRACK ka.

UPDATE Media parameters final karne ke liye UE1 UPDATE bhejta hai SDP ke saath. Codecs aur RTP ports dono side confirm karte hain. 200 OK (UPDATE) wapas aata hai.

180 Ringing UE2 ka phone actually ring bajne lagta hai. 180 simple provisional response hai — PRACK ki zaroorat nahi. UE1 tak pahunchta hai.
04 Call Answer — UE2 picks up · 200 OK · ACK 200 OK (INVITE) · BYE to ANNC · ACK · t≈36.96s
UE2 ne phone uthaya!

200 OK UE2 phone uthata hai → 200 OK (INVITE) Record-Route path se wapas jaata hai. Saath hi SDP confirm hota hai — media session ready hai.

Ringback Band TAS ko 200 OK milta hai → TAS turant Announcement Server ko BYE bhejta hai — ringback tone ruk jaati hai. Ab actual call connect ho rahi hai.

ACK UE1 ACK bhejta hai — SIP three-way handshake ka last step. ACK bhi same path se jaata hai UE2 tak.

Call Established ACK ke baad RTP media stream directly UE1 ↔ UE2 ke beech shuru ho jaati hai (P-GW / IMS-DP ke through, SIP signalling mein nahi aata). Dedicated voice bearer already create ho chuka hota hai (PCRF ne AAR/AAA se authorize kiya tha 183 pe).
05 Call Teardown — BYE (UE2 initiated) BYE · 200 OK · TAS dual-leg teardown · t≈45.5s
Call kaise khatam hoti hai?

UE2 BYE bhejta hai Wireshark mein t≈45.5s pe UE2 ne BYE bheja (pehli call mein). BYE P-CSCF → S-CSCF → TAS path se jaata hai.

TAS dual-leg teardown TAS ek B2BUA ki tarah kaam karta hai — matlab TAS ke paas do alag dialogs hain: ek UE1 ke saath, ek UE2 ke saath. Jab UE2 BYE bhejta hai, sirf UE2 ka dialog close hota hai. TAS ko UE1 ka dialog bhi manually band karna padta hai — isliye TAS ek alag BYE bhejta hai S-CSCF → P-CSCF → UE1 ki taraf. UE1 200 OK bhejta hai.

Clean teardown Sab dialogs properly 200 OK se close ho jaate hain. PCRF ko STR (Session Termination Request) milta hai → dedicated voice bearer release hoti hai → CDF CDR generate karta hai (call duration, parties, media type).
